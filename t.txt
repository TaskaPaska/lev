## 4. Cheat-sheet: how to solve a similar midterm fast

A reliable order of operations — do them exactly in this sequence, it minimizes rework:

1. **Label every device and every link** on paper. Write interface names (Fa0/0, Fa0/1...).
2. **Make the IP table first.** One row per subnet. Fill before you touch any device. Use:
   - `/30` for every router-to-router link
   - `/24` for every LAN / VLAN
   - A distinct `/24` block for each NAT "global" advertisement
3. **Configure interfaces + IPs everywhere.** Nothing else yet. `ping` each direct neighbor.
4. **Bring up the IGP (OSPF).** One `router ospf 1` per router, `network ... area 0` for every interface that participates. Verify `show ip ospf neighbor` and `show ip route ospf`.
5. **Add the GRE tunnel** (source/destination use the already-working WAN IPs). Put a `/30` on `Tunnel0` on each side.
6. **Add RIP** only on the VPN routers, include the LAN networks and the tunnel's `172.16.0.0` network. Verify RIP routes appear across the tunnel.
7. **Static & default routes:** VPN routers get a default toward R1; R1 gets statics to each VPN global; R4 gets static to L3-switch global; R5 gets default to R4.
8. **Redistribute statics into OSPF** on the routers that own them (`redistribute static subnets`). On R5 use `default-information originate` to push the default into OSPF toward R6/R7.
9. **VLANs + trunks + EtherChannel** on the L2 switches. Always define the VLAN on every switch that carries it. Keep `channel-group` **mode consistent** on both ends.
10. **HSRP last** (it needs the SVI's IP already working). One priority higher on the "active" side, add `preempt`, `standby X ip <VIP>`. Hosts use the VIP as their gateway.
11. **NAT last-last.** Mark `ip nat inside` / `ip nat outside` on the right interfaces. Define ACL + pool (or static). Verify with `show ip nat translations` while pinging.

### Cisco commands you MUST memorize

```text
show ip interface brief
show ip route
show ip ospf neighbor
show ip protocols
show cdp neighbors
show standby brief
show etherchannel summary
show interfaces trunk
show ip nat translations
debug ip nat             ! turn off right after!
```

### Typical gotchas under exam time pressure

- Forgetting `no shutdown` on a router interface.
- Forgetting `ip routing` on a multilayer switch — without it, L3 switch acts as L2 and HSRP/OSPF won't work.
- Mismatched `channel-group` modes (one side `active`, other side `on`) — the port-channel stays down.
- Forgetting `ip nat inside` / `ip nat outside` — NAT silently does nothing.
- Forgetting `redistribute static subnets` — remote routers won't see the NAT globals.
- `network` statement in OSPF with wrong wildcard mask — keep it simple: `/30` → `0.0.0.3`, `/24` → `0.0.0.255`.
- In GRE: `tunnel destination` must be an address already reachable *before* the tunnel comes up (i.e., the underlay must be fine first).

### If the real exam gives you different addresses

Replace only:
- Every `/30` on my WAN table with the exam's equivalents.
- Every `/24` LAN with the exam's LAN `/24` — but keep the rule "`.1` = router/gateway, `.10/.20` = hosts, last usable = HSRP VIP if L3-switch LAN."
- The GRE tunnel still gets its own private `/30` (you choose it, e.g., `172.16.99.0/30`), independent of the exam's assignments.
- NAT "global" pools: use whatever the exam calls the outside network.

Everything else — commands, order, structure — stays **identical**.
